4.3 Backpressure & admission
What waits, and what keeps running?

    
4.4 Key concepts
CAPTURE
Parameters travel with instructions
IF supplies GPR read indices. ID operand-use controls select the read values captured into EX. Later scalar writes cannot change parameters in an accepted command.
FORK
Start launches hardware work
The target progresses independently after launch. Scalar continues after the command response. Acceptance, launch and whole-job completion are distinct events.
JOIN
Sync waits in EX
A pending sync retains EX ownership and backpressures admission. Engines keep running, and older WB work may still retire. The response releases scalar execution.

5.2 Routing rules & implementation scope
What changes each cycle?
Each butterfly stage chooses straight or exchange routing. H1, H2 and H4 exchange rows at distances 1, 2 and 4. Their local selectors have different initial offsets; a single global square wave per stage is insufficient. These are mux controls in one clock domain, not divided clocks.
The highlighted path runs from bank to consumer. Writes use the corresponding inverse permutation. A channel visits every bank exactly once per eight-phase teaching tour.
What the simplified slide leaves out
Current DTCM has 16 × 64-bit banks. Fast O/P storage streams use 256-bit beats; slow I/O/P BF16 streams use 128-bit beats. These service classes coexist in the wide schedule. Indexed reorder state restores logical beat order after physical rotation.
LSU, ACTU and CMPU consume the slow service through adapters and buffering. ACTU/CMPU own explicit read queues and write FIFOs; the LSU boundary forwards ready/response. Shared admission, credits, row carries and dependencies still matter. Fixed rotation does not guarantee bubble-free execution.
